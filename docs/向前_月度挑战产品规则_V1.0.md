# 向前｜月度挑战产品规则 V1.0

**版本：** 1.0  
**产品：** 向前（Android）  
**模块：** 月度挑战  
**状态：** 产品规则基线  
**开发状态：** 未开始

---

## 1. 产品定位

月度挑战是向前的独立成长系统。

它不负责管理日常任务，也不负责替代原有自律约束。它通过每月一次的主动挑战，引导用户实现超出日常行为水平的能力突破、创造交付、生活探索或行为改变。

核心体验：

**收到挑战书 → 接受承诺 → 经历挑战 → 提交成果 → 获得奖励 → 留下成长记录。**

### 1.1 产品目标

1. 让用户产生主动接受挑战的意愿。
2. 让挑战具有明确难度，而非简单增加任务数量。
3. 让用户能够在一个月内完成真实、可验证的改变。
4. 通过愿望、故事、神秘内容和艺术收藏提高参与动力。
5. 让每次挑战成为长期成长档案的一部分。

### 1.2 非目标

V1.0 不包含：

- 公开社区、排行榜和实时社交。
- AI 自由生成挑战。
- 在线好友账户和实时同步。
- 独立的复杂等级系统。
- 强制增加每日必做任务。
- 以娱乐额度惩罚挑战失败。
- 需要付费服务器才能运行的功能。

## 2. 挑战周期与发放机制

### 2.1 周期

- 使用设备当前本地时区。
- 每个自然月为一个挑战周期。
- 每月 1 日生成当月推荐挑战。
- 挑战接受窗口为当月 1 日至 7 日 23:59。
- 挑战执行截止时间为当月最后一天 23:59。
- 未接受的挑战不视为失败，不产生任何惩罚。

如果用户当月没有打开 APP，挑战不会因为错过推送而自动判定失败。

超过接受窗口后，本月不再补发常规挑战，等待下一个周期。

### 2.2 推荐机制：Recommended

系统每月只展示一个主推荐挑战。

推荐过程采用本地规则引擎，不依赖 AI 或网络。

候选挑战必须通过以下筛选：

1. 模板已经完整配置并处于发布状态。
2. 剩余周期足够完成挑战。
3. 预计额外投入符合用户可接受的时间预算。
4. 不与正在进行的其他挑战冲突。
5. 不重复推荐近 6 个月已经完成的同一模板。
6. 尽量避免连续两个月推荐相同类别。
7. 不推荐已经明确不适合当前条件的挑战。

在合格候选中，优先选择：
- 用户近期较少接触的成长类别；
- 与历史挑战结果形成互补的类别；
- 当前时间预算下最可行的挑战。

推荐时展示简短推荐理由，例如：

> 你最近没有进行创造类挑战，本月推荐一次小型作品交付。预计额外投入 4—6 小时。

推荐理由必须来自真实数据，不能伪造用户画像。

### 2.3 更换规则：One

1. 首次收到挑战书时，可以直接接受、跳过或更换。
2. 更换后，系统从剩余合格候选中提供一个替代挑战。
3. 更换机会立即消耗。
4. 更换后的挑战只能接受或跳过。
5. 不允许恢复原推荐，也不允许再次更换。
6. 接受挑战后，不再允许更换难度、模板或奖励。
7. 跳过后，本月不再发放其他主挑战。

更换不是重新随机整个挑战库，而是从已经筛选出的有效候选中选择替代项。

如果没有合格替代挑战，直接提供跳过选项，不生成不合理的挑战。

### 2.4 接受前的配置

接受前，用户需要确认：

- 挑战难度；
- 基准测试结果；
- 预计时间投入；
- 现实愿望；
- 是否启用好友见证；
- 挑战证据及验收方式。

难度只能在接受前修改。

接受后，挑战实例冻结。

## 3. 挑战类别

V1.0 设置四大类别：

| 类别 | 核心目标 |
|---|---|
| 能力突破 | 独立完成此前无法完成的事情 |
| 创造交付 | 从想法形成完整作品 |
| 生活探索 | 体验不同于日常的生活内容 |
| 行为重塑 | 通过行为实验改善一种习惯 |

所有挑战必须具有可识别的起点、行动过程和最终验收标准。

不能仅凭主观感受判定挑战成功。

## 4. 难度系统

所有挑战设置三个等级：

### 进阶

超出用户目前的日常水平，但有较高可完成性。

### 突破

需要持续投入、解决真实问题，最终成果明显超出基准状态。

### 极限

需要完成高难度、独立性更强或更复杂的成果。

三个等级不使用统一的任务数量倍增公式。

每个挑战模板分别定义难度参数、证据要求和验收条件。

难度必须在接受前确定。

## 5. 挑战执行规则

### 5.1 挑战阶段

每项挑战包含：

1. 挑战书：介绍主题、目标、规则及奖励。
2. 基准阶段：记录接受挑战时的实际状态。
3. 行动阶段：完成预设的里程碑。
4. 验收阶段：提交最终成果并判断是否达标。

每项挑战原则上设置 3—4 个里程碑。

### 5.2 进度计算

进度必须依据已完成的里程碑及其权重计算。

不允许仅根据打开 APP 的次数、打卡次数或阅读信件的次数增加进度。

如果某个里程碑需要人工验收，必须通过验收后才能计入完成。

### 5.3 暂停与退出

- 用户可以主动暂停挑战。
- 暂停时保存所有进度和证据。
- 恢复后继续原挑战。
- 暂停不自动延长自然月截止时间。
- 用户可以主动放弃。
- 放弃不影响每日任务、XP 历史和娱乐额度。
- 月底未完成的挑战归档为部分完成或未完成。

暂停与退出均需要记录时间及原因。

## 6. 故事、神秘与探索机制

每项挑战包含四个内容节点：

| 节点 | 触发 | 内容 |
|---|---|---|
| 挑战书 | 发放 | 开场故事、目标、邀请 |
| 第一封回信 | 第一个关键里程碑 | 阶段反馈 |
| 深入篇章 | 第二个关键里程碑 | 新的视角或可选探索 |
| 最终回信 | 结算 | 真实结果与成长记录 |

故事内容不能改变验收规则。

隐藏内容只能用于额外探索、收藏或故事体验，不能隐藏成功条件。

第一版允许通过预置内容实现惊喜，不需要 AI 实时生成。

## 7. 奖励系统

挑战奖励分为四类：

### 7.1 现实愿望

用户接受挑战时绑定一个具体愿望。

挑战成功后获得愿望兑现资格。

APP 只负责记录承诺及兑现状态，不负责代替用户购买物品或管理资金。

### 7.2 XP

挑战成功后发放对应难度的挑战 XP。

具体数值采用独立配置，正式确定前必须对照现有 XP 曲线，避免挑战奖励破坏等级成长速度。

XP 只发放一次。

### 7.3 艺术收藏

每项挑战拥有专属艺术收藏。

完成后解锁对应收藏卡，难度可影响收藏版本或装饰细节。

未完成挑战不发放成功藏品，但可以保留普通过程记录。

### 7.4 身份成长

挑战记录进入长期成长档案。

身份印记基于真实挑战经历产生，不单独建立一套与现有等级冲突的经验体系。

建议：
- 首次完成挑战：获得启程印记。
- 完成同一成长类别的 3 次挑战：解锁对应类别印记。
- 完成 5 次不同类别挑战：解锁综合成长记录。

具体名称与视觉形式由现有成就系统统一设计。

### 7.5 娱乐额度限制

V1.0 不通过月度挑战直接发放视频分钟或游戏局数。

未来如需增加娱乐权益，必须经过现有奖励账本，并服从每日获取上限、每日使用上限和睡眠惩罚。

不得绕过现有行为约束。

## 8. 好友挑战

V1.0 仅支持离线分享：

- 分享挑战书；
- 分享阶段成果；
- 邀请好友见证；
- 记录好友反馈。

好友见证属于辅助证据，不自动替代客观验收。

不建设在线好友系统。

## 9. 最终结算状态

| 状态 | 含义 |
|---|---|
| 已完成 | 所有必要验收条件通过 |
| 部分完成 | 至少完成一个关键里程碑，但未达到最终标准 |
| 未完成 | 未达到主要里程碑或最终条件 |
| 已放弃 | 用户主动退出 |
| 已跳过 | 用户未接受推荐 |
| 已过期 | 接受窗口结束仍未接受 |

挑战失败不扣除日常奖励、不降低等级、不增加睡眠惩罚。

已完成的挑战只允许结算一次。

## 10. 数据与隐私

- V1.0 本地优先。
- 不上传个人挑战数据。
- 证据文件默认保存在本机。
- 允许用户删除非必要证据。
- 备份必须包含挑战实例、进度、证据索引和奖励结算记录。
- 分享行为必须由用户主动发起。

## 11. 版本范围

V1.0 必须交付：
- 推荐与更换；
- 挑战书；
- 难度选择；
- 愿望绑定；
- 四类挑战模板；
- 里程碑和证据；
- 最终验收；
- XP 与艺术收藏；
- 成长档案；
- 本地备份恢复。

V1.0 暂不交付：
- 在线社交；
- AI 挑战生成；
- 实时好友对决；
- 年度剧情；
- 复杂隐藏挑战系统。

**最终原则：每一项正式挑战都必须能够执行、验证、结算和归档。**
