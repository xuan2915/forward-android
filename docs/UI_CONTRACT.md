# 向前｜界面约定

## 产品 UI/UX 强制约束（2026-11-22）

适用于所有 UI 新增、修改和重构。实施时保留原有数据、业务规则、无障碍语义及功能可达性。

1. **信息架构。** 每页明确一个核心用户目标，按用户任务和使用频率组织内容。高频操作放主要页面，低频设置、详情和历史数据放二级页面。关联信息按主次呈现，禁止为展示功能齐全而把不同模块堆在同一页。
2. **卡片使用。** 普通列表优先用文字、行布局、留白和轻分隔线。只有需要强调独立内容、交互边界或状态时才使用卡片。禁止逐项套卡，以及用多层容器、底色、描边和阴影制造层级。
3. **信息密度。** 首屏优先呈现核心状态、当前任务和主要操作。次要信息可折叠、进入详情、切换标签或按需展开。避免无意义的大间距拉长页面，删除重复数据、入口和状态，以及多余的说明、副标题、徽章与装饰。
4. **视觉层级。** 每页只设一个首要视觉焦点，突出主要操作，弱化次要操作，清晰区分危险操作。优先用排版、字号、字重、对齐和留白组织内容。颜色、卡片、图标和动画均须有明确用途。
5. **修改前检查。** 当前页面适合承载这项功能吗？是否应放二级页面？能否复用现有入口或组件？核心操作是否更难找到？原有层级是否受损？发现冲突先调整信息架构与布局，再处理视觉细节。
逐句检查用户可见文案：同一事实只说一次。删除复述标题、按钮或徽标的正文、教学式解释和无关安慰语。只在需要时展示权限用途、风险后果和错误原因；保留必要单位、动作标签及读屏语义。

6. **重要修改的验收。** 查看实际页面并走通主要操作：用户能否快速识别核心任务？最高频操作是否容易找到？是否有无关功能争夺注意力？哪些卡片、边框和说明可以取消？主要功能是否完整且易达？依据用户任务、使用频率和认知负担决定哪些内容立即展示，哪些按需访问。

本轮执行顺序：收到用户转来的 Gemini 修改回执后，由 Codex 只读检查候选版本。逐项记录页面、入口或操作状态、违反的条款、对用户的影响及截图或录屏证据。统筹先向用户报告不符合项及未测范围，再交 Gemini 修改；修后由 Codex 按同场景复验。

目标时长：小时、分钟是两个固定数字输入框，不是滚轮。在两框的右侧提供展开入口；正文点按始终是数字输入。展开后在独立浮层中选小时和分钟，参考手机闹钟选择器的跟手滚动、减速与吸附。可用空间不足时仅列表内部滚动，不能撑开表单、推动输入框或带动底层页面。禁止模式按钮、在关闭状态拖数字改值和重复说明。

周回顾（用户确认）：可查看历史周，标题固定为「周回顾」，不随选周变成「本周实际完成」或「周实际完成」。日期范围标识所选周，「本周」只用作返回当前周的动作；空态不重复标题，不暗示没有记录就等于没有行动。这不改变其他确实只统计本周的指标。

2026-11-19，产品负责人确认。Linear 官网与苹果备忘录是清晰、克制的方向参考，不是复制皮肤的要求。

- 每页先确定用户来做什么。标题、主要内容与可用操作依阅读顺序排列；次要内容按需展开，不与主任务争夺注意力。
- 删除标语、教程式说明、重复标题和次要标签。需要一段话解释两个数字为何不同，先重排数字与所属对象；不要把说明换成徽章或图标堆。
- 极简不等于缩字号、降对比或隐藏入口。保留必要的单位、日期、动作名称、真实空态、无障碍名称，以及不可逆操作的后果说明。
- 同一调整同时检查三件事：用户少猜一步；开发者不维护第二套组件或数据口径；后续执行者能从唯一规则和验收样例还原行为。不为追求统一而抹去业务上真实的差异。
- 验收用相同数据、相同页面状态对比前后，验证关键操作、空态和辅助功能语义。未测试的设备与场景明示，不承诺零风险。

成长页例：日历围绕计划日组织，周回顾列实际完成记录。二者不强求同一天；界面用内容归属和必要日期字段表达，不依赖常驻解释段。此决定取代 FWD-007 的图例说明方案，不改变统计规则。

## 2026-11-24 页面归属补充

- 夜间收尾页只保留独立的收尾提醒。娱乐限制与抵扣管理统一由睡眠管理承载，避免并行入口和重复规则。
- 奖励页聚焦余额、获得/使用与必要流水查阅。应用保护移至设置的应用保护页，紧急解锁移至设置独立页；已有学习窗口放到合适的二级入口并保持可达。
- 对涉及历史扣减或奖励的页面整理，先核对真实账本和结算路径，保留真实历史流水；不得通过隐藏展示解决尚未查清的统计或重复扣减。
- 任务表单的“验收要求”区域本轮不改，等待产品负责人之后指定。
